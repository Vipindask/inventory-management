Data flow

A single request path serves every screen. Filters are the only input the system takes.

  1. User adjusts a filter
    FilterBar.vue writes to the shared refs in useFilters — period, warehouse, category, order status.
  2. Views react
    Each view watches the filter state and calls getCurrentFilters(), which maps period to the API's month parameter.
  3. api.js builds the request
    Any filter still set to 'all' is omitted, so the query string carries only active constraints.
  4. FastAPI filters in memory
    apply_filters() narrows by warehouse, category and status; filter_by_month() resolves a month string or expands a quarter through QUARTER_MAP.
  5. Aggregate where needed
    Summary and report endpoints compute totals, fulfillment rates and averages over the filtered set on every call — nothing is cached.
  6. Pydantic validates the response
    Typed endpoints coerce and check each record against its model before serializing to JSON.
  7. Vue stores raw, derives computed
    Responses land in refs such as allOrders and inventoryItems; every displayed number is a computed property over those refs.
Filter dimensions
  • Time period — a month (2025-03) or a quarter (Q1-2025). Applied to order_date.
  • Warehouse — exact match on the warehouse field.
  • Category — case-insensitive match on category.
  • Order status — case-insensitive match; Delivered, Shipped, Processing, Backordered.
Not every filter reaches every endpoint. Inventory accepts only warehouse and category — it has no time dimension. Demand, backlog and the spending endpoints accept no filters at all and always return the full set.
Client-side state
  • Singleton composables — useFilters, useI18n and useAuth declare their refs at module scope, so every importer shares one instance.
  • Locale drives currency — selecting ja switches formatting to JPY; the choice persists in localStorage.
  • Raw in, derived out — API payloads stay untransformed in refs; totals, groupings and chart series are all computed properties.

Architectural constraints
  • Demo posture — no authentication, no rate limiting, CORS open to every origin. Local development only.
  • No write path — the server never mutates its in-memory lists, so the API is effectively a read replica of the fixture files.
  • Filtering scales linearly — every request re-scans full Python lists. Fine at 250 orders; a database boundary is the natural next step.
  • Hard-coded API base URL — api.js points at localhost:8001, so deploying anywhere else requires a config change.
